# 体素角色动画制作

把体素角色做成可预览、可切换动作、可导入游戏的动画资源。按用户请求处理当前阶段；已有绑定或动作时先检查并复用，不从头重做。

## 先确认实际状态

- 检查当前文件、选中对象、网格实例、材质/UV、朝向、尺寸、骨架、Action、Action Slot、播放范围和蒙皮修改器。
- 优先使用可用的 Blender MCP 操作现场；需隔离处理或导出验证时，用 Blender 后台 Python。后台文件已保存，不等于现场窗口已刷新。
- 作者文件与游戏导出文件分开保存；导出前读取现场状态，必要时保存副本。用户认可的动作保留，新方案另建 Action。
- 仅对影响工作的未知信息澄清。例如“动画都不动”先区分 Blender 预览与引擎播放，同时检查本地数据。

## 1. VOX 导入与场景检查

已有 VOX 转换器时沿用其实际 CLI 和配置，避免猜测参数。保留身体分件、贴图、UV 与变换，明确单位、向上轴和前进方向。

glTF 节点必须形成无环、单父节点的层级。重新挂接节点时同时解除旧父节点的 children 引用；检查所有节点，包括场景之外的旧包装节点。复用 mesh 数据不代表可以让同一个 node 同时属于多个父节点。

先实际导入 Blender 验证模型、颜色、肢体位置和比例，再制作动作。

## 2. 绑定适合角色的骨架

简单分件体素角色可采用刚性蒙皮：每个身体部件全部顶点以权重 1 绑定到对应骨骼。

- 以髋部作为整体位移/旋转控制，身体、头、双臂、双腿形成合理父子关系。
- 骨骼数量不设固定值或默认数量；根据角色结构、关节活动、动作表现和目标引擎性能需求选择合适的骨架。需要屈肘、屈膝、脊柱弯曲等表现时设置相应关节，不能把缩放肢体称作真正的膝盖弯曲。
- 左右肢体若共享 mesh 数据，在分配不同顶点组/权重前复制 mesh 数据，避免权重覆盖或摆动抵消。
- 使用角色坐标与骨骼静止矩阵计算关节和局部轴，不假定局部轴等于世界轴。
- 即使髋骨没有直接权重，也可能控制全部子骨骼，不能作为“无用骨骼”删除。

验证修改器指向正确骨架，改变骨骼姿态确实改变模型顶点，而非仅检查关键帧存在。

## 3. 制作可独立切换的动作

每个动作使用独立命名的 Action，并保留其数据。先制作接触、通过、腾空、落地等主要姿态，再设计插值。作者文件保留稀疏关键姿态；运行时导出可按目标引擎能力采样。

动作切换要独立于上一段动作：对需要复位但不参与运动的骨骼通道，保留一个常量复位关键帧。特别检查整体旋转、位置与缩放，防止“睡觉 → 行走”继续保持躺姿。

制作、简化曲线或排查预览时，读取 [references/blender-animation.md](references/blender-animation.md)。

## 4. 调整循环、节奏和辨识度

- N 帧循环的第 N+1 帧复制第 1 帧姿态，预览播放 1–N；导出保留 N+1 帧，使片段时长为 N/fps。
- 检查接缝两侧姿势与速度连续性。切换动作后同步播放范围，错误范围会制造跳步或停顿。
- 区分“幅度大”“频率高”“曲线不连续”。用户说抖时，先检查接触修正、左右节拍、曲线尖点和范围，不直接把幅度全部压低。
- 奔跑辨识度来自前倾、手脚对摆、蹬地、摆腿回收和双脚腾空。仅加快行走或只抬高身体，仍可能像走路/原地蹦跳。
- 嫌晃眼时可保持姿态与腾空，仅统一延长关键点及手柄的时间坐标；喜欢当前感觉但要更夸张时，另建动作放大姿态。
- 精简要保留接触、极值、速度与常量复位通道；按模型空间误差判断，不能机械隔帧删键。

## 5. 整理游戏导出副本

列出必要网格、骨架与动作白名单。依照用户范围移除道具、灯光、相机、空包装及道具驱动；“只要角色”时附加眼皮也可能属于应删除的道具。

同材质分件可合并为一个蒙皮网格，保留 UV、权重与坐标关系；合并、重挂接前后比较多个动作的顶点。不要应用 Armature 修改器把骨骼变形烘死在静态模型上。

GLB 可一起包含模型、内嵌贴图、材质、骨骼、权重和片段。该角色已完成绑定，引擎中配置状态机即可选择动作；重定向到另一套角色骨架属于另外的工作。

导出时读取 [references/game-export.md](references/game-export.md)，包含 Blender 选项、层级精简与 Laya 使用说明。

## 6. 验证与交付

验证本次改动影响的部分：

1. 在 Blender 切换动作，抽样检查真实网格变形、接触与循环。
2. 检查导出文件的层级、蒙皮、片段名、时长与资源；有条件时运行 Khronos glTF Validator。
3. 新临时场景回导，逐片段比较时长与姿态。导入可能生成骨骼显示辅助 mesh，计数时识别实际蒙皮网格。
4. 有目标项目时再验证引擎播放。格式检查、Blender 回导通过，不等于已在 Laya 中运行通过。

保存预览 `.blend` 时仅选骨架作为活动对象，进入姿态模式，绑定有效 Action/Slot，设置对应范围。开始实际播放并读取现场状态确认。“动作被误挂到网格”是不动时的优先诊断项。

随附结构检查工具：

```bash
python3 <skill-dir>/scripts/inspect_gltf.py character.glb --expect-animations 7 --character-only
```

它只检查结构，不能替代完整格式校验、顶点变形对比或引擎运行。
